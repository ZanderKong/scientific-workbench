## 2. 阻断交付的问题

优先级 P1 表示应在依赖该功能或存放正式研究内容前修复。以下“复现”来自 scripts/audit-reproduction.mts，原始结果为 [reproduction.json](./reproduction.json)；其他发现标注为代码审查。

### R-01 [P1] 保存状态与数据丢失/串写风险（代码审查）

apps/web/src/main.tsx:39、55–68：顶栏固定显示“本地已保存”。样品仅有 500 ms debounce，没有持续输入 2 秒保存上限、浏览器草稿恢复、切页保存/提取和请求串行化。save 捕获错误不向 finalize 抛出，保存失败后仍能提取旧正文并显示成功。

Data 的 change 先 setBody 再调旧闭包的 save，定时提交的是前一次渲染的正文。DataEditor/AnalysisEditor 没有按实体 ID 的 key 或状态重置，切换同类型实体时旧正文状态可能沿用到新 ID。Analysis 吞掉保存错误后仍显示“分析已保存”。

修复验收：连续输入、断网、切换两个 Data/Analysis、保存与 finalize 交错；核对实际文件而不是提示文字。对应 PARSE-001、TEST_PLAN P-03、coding plan 2.4。

### R-02 [P1] 文件并非完整事实源，无法独立重建（复现）

apps/server/src/store.ts:47、130–156：对象/属性字典、附件登记、历史、证据及多数关系只存 SQLite。Data/Analysis/Claim Markdown 没有完整实体元数据。样品解析创建的 Data 甚至未写独立文件。rebuildIndex 仅 INSERT OR IGNORE 样品。

去掉索引、仅复制业务目录重建后：对象、Data、Analysis、Claim 均为 0。不能把 SQLite 称为可重建轻量索引。写入采用文件替换与独立数据库操作，没有持久化写入恢复日志、数据目录单写锁及崩溃恢复协议。对应 CORE-001、PROJ-001、coding plan 2.1/2.4。

### R-03 [P1] 备份成功与可恢复性不成立（复现）

apps/server/src/store.ts:155–156；apps/server/src/storage.ts:24–35：备份只扫描现存本地文件，不取回远端唯一附件，也不锁定一致集合。模拟附件远端唯一且本地缺失，仍报告备份成功。

恢复携带旧 SQLite 的绝对 file_path，INSERT OR IGNORE 不更新路径。复现显示恢复验证成功但 readDocument 指向原目录；原目录消失后无法独立读取，继续编辑也有写回旧目录的风险。恢复还允许已有非空目标目录，未实现“全部验证后切换工作区”。对应 STORE-004、TEST_PLAN Q、coding plan 3.4。

### R-04 [P1] S3 密钥进入备份；授权不是真正的 scope（复现＋代码审查）

storage.ts:18：configure 把含 accessKeyId/secretAccessKey 的完整配置写入 settings，又额外写 private 文件。备份包含 SQLite，因此排除 private 仍不能排除密钥。使用虚构密钥复现，未触及真实凭据。

main.ts:17–23：无环境 token 时跳过全部授权，有 token 时危险权限仅检查请求方可自行添加的 x-workbench-scope。没有凭据绑定的权限授予/撤销、UI 会话和 Host 检查；CORS 白名单不能代替鉴权。MCP request 也不发送认证头，开启 token 后桥接不可用。对应 AI-001、coding plan 3.3。

### R-05 [P1] Data 多入口共享只做了名称局部同步（复现＋代码审查）

parser.ts:83 使用 children.find，只处理第一个 Data；store.ts:103–111 为它创建空正文。两个 Data 子区块复现只得到一条 Data，子正文未进入 Data。没有内容基线哈希、区块编辑状态、冲突草稿交互或多引用同步。Data 页面也缺 About 编辑、附件预览/下载与正式论点入口。

对应 DATA-002/004、CLAIM-002、coding plan 3.1。

### R-06 [P1] 论点证据及导出范围不符合约定（复现＋代码审查）

store.ts:142–146：Analysis host 只快照 analysis.body，版本固定为 1；复现仅得到“分析正文”，没有分析涉及的样品和 Data。附件只记录 ID，未快照完整清单/哈希。创建论点不先提交待提取文档。

main.ts:76–82：导出只包含直接 itemIds，缺直接样品的 Data、字典、必要 About 说明、实体版本/附件哈希、分实体文件和阅读版去标记。ensureLatest 吞掉提取异常，导出不据此失败。前端只下载 context 字符串，manifest 未导出。

对应 CLAIM-003、VIEW-001、TEST_PLAN P-02/P-03、coding plan 3.2。

### R-07 [P1] 区块身份按行序套回，不能保证来源身份（代码审查）

main.tsx:16–20：mergeBlockIds 按 bullet 顺序复用旧 ID，而非 ProseMirror 区块节点身份。顶部插入、删除、移动会把旧 ID 分给其他操作；UniqueID 产生的节点身份没有接入此序列化。Data ID 又依赖这些区块 ID，因此影响数据关联，不只是显示问题。

补全只读取文档最后一行，无光标位置、composition 保护、规定的最近/高频排序；新对象一律 material。没有默认 bullet、折叠、层级规则与专用附件节点。普通 StarterKit/Markdown 并不等于已实现这些规则。

对应 EDIT-002/006、OBJ-003、coding plan 2.2/2.3。

### R-08 [P1] 外部编辑“重新加载”无法完成后续编辑（复现）

main.ts:57 的 reload 只读取文件，不更新已接受磁盘基线；前端还不更新版本/head。正文从 5 g 外改为 6 g，读取后再保存仍报“请先重新加载”。Data/Analysis/Claim 的外改检测也没有实现。对应 coding plan 2.2。

### R-09 [P1] 属性与引用持久化链路不完整（复现＋代码审查）

store.ts:70 listSamples 没有 properties，main.ts:40 却读取 s.properties，因此前端属性面板拿不到值；详情查到 1 条而列表无该字段已复现。

finalize 只处理属性和第一条 Data，不保存完整对象引用/绑定。无属性的过程引用无处索引；对象改名后依赖旧名称的正文再次提取会失去属性。重复 finalize 删除重建属性记录并增加 usage_count，不满足稳定记录与真实使用频率。未绑定项被跳过，无完整提示状态。parser.ts:28 不拒绝属性值中第二个对象造成的歧义。

对应 CORE-002、EDIT-008、LIFE-001、PARSE-002、SAMPLE-002。

### R-10 [P2] API/MCP、历史、S3 任务和样例覆盖不足（代码审查）

- MCP 仅 15 个工具，不能完成 Data 创建编辑、分析创建编辑、附件组件关联等完整流程。版本条件可省略、无创建幂等键、分页、取消、完整错误规范。
- 历史仅样品保存时记录旧正文到 SQLite，非完成编辑快照；Data/分析/论点缺历史。没有历史查看 UI。
- S3 LIMIT 2 是每小时最多顺序处理两个，并非持续队列并发 2；无指定退避和持久任务错误。附件远端读取传 camelCase 对象，但 presigned 读取 remote_key，无法拿到上传位置。无 2 GB 缓存实现。
- demo 的三次冻融只改“循环次数”为 3，没有三个独立操作；设备名没有空格案例，没有 PNG、大附件、时钟边界测试，未形成约定完整实验。

## 4. 对 coding plan 本身的评估

技术选择总体可沿用，不需要重新讨论已经确定的对象/属性语义。计划已明确要求继承原型和完整首版，不能解释成允许替换产品布局或省略工作流。

计划需要修正执行约束：

1. 原型视觉对齐放到第 7 阶段太晚。开工即固定导航、默认列表、页面结构、字号/间距/配色；用同视口截图验收，之后每阶段维护。
2. 缺少逐页面的控件—动作—API—数据—测试映射。比如“动态列”必须实际选列、显示、保存设置、点击定位，不能以已有 properties 表宣称完成。
3. 在 UI 铺开前证明一个完整链路：编辑 → 落盘 → 关闭重开 → 提取 → 表格 → 来源定位；再添加 Data 等链路。
4. 文件格式先证明独立重建与备份独立恢复；不能一边说文件优先、一边临时把关系只塞数据库。稳定区块与文件/索引恢复协议先做具体实验。
5. 每阶段采用明确“未实现/部分实现/已实现未验证/已验证/已知失败”状态，附测试和截图。无测试的阶段不能凭 build 成功通过。
6. 把批准的 coding plan 持久化并纳入规则/测试映射；更新过期状态文字，但不自行改变产品规则。

建议整改顺序：先修正文保存、文件事实源、区块身份及备份/授权风险；同时以原型结构重建 UI；随后逐条完成样品、Data、分析/证据、MCP、S3/备份完整闭环。沿用可用技术栈和解析基础；当前页面和持久化链路需要实质重做，不能只换皮。
