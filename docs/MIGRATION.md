# 旧工作区转换

[返回项目首页](../README.md) · [使用指南](GETTING_STARTED.md)

先完成 `pnpm install --frozen-lockfile` 和 `pnpm build`，保留旧目录的完整副本。转换器已在隔离夹具上验证；你的实际旧工作区仍需核对输出报告、正文、附件及关系，不能只看命令退出码。

旧 swb/1 工作区不能原地打开。先停止使用旧目录的应用，在项目目录运行：

```sh
pnpm migrate:legacy --source /旧工作区绝对路径 --destination /尚不存在的新目录
```

两个路径必须明确指定；目标不能位于旧目录内、不能已经存在。工具不会自动切换正在运行的服务。先查看输出报告，再以新目录显式启动：

```sh
WORKBENCH_DATA_DIR=/新目录 pnpm start
```

转换器读取旧 Markdown、旧 index/workbench.sqlite 的隔离副本、历史与证据 JSON，以及本地附件。样品、Data、分析、论点、字典、About、组件、来源、条目顺序、正文历史和原有证据写成新版文件；不复制旧 SQLite、凭据或运行配置。若旧 Sample ID 与 Document ID 不同，保留 Sample ID并在报告记录文档身份映射。

正文文件优先于旧索引；缺 Markdown 时可从已有索引恢复正文并报告。附件先校验原字节，复制后再校验。未登记附件保留在新目录 attachments/unregistered，并在报告列出，供人工关联。远端唯一附件缺本地字节时转换失败，先通过旧系统取回文件；工具不会猜测旧凭据或自动访问远端。

无法确认的 Data 区块进入“数据待关联”，保留两边内容，等待选择已有 Data 或明确新建。旧论点显示“旧格式证据不完整”，只保存当时实际留下的快照；不会用当前数据补造过去证据。

发布新目录前重建索引并逐篇核对阅读正文哈希，再检查来源文件有无变化。转换期间源目录变化、字节缺失、证据哈希错误或路径不安全都会失败，不发布目标工作区。目标旁保留独立 migration 报告；成功后新目录 registry/migration-report.json 也保存报告。`verified` 表示转换验证通过，报告中的待关联、缺关系和旧证据警告仍需处理。

隔离测试已覆盖：旧目录逐文件哈希不变；移走旧目录并删除新索引后重建；组件字节与旧证据可读；旧凭据不进入新目录；缺附件不发布；目标已有文件不覆盖；独立历史/证据文件与未登记附件保留。未在实际用户工作区执行转换。
