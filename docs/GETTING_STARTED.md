# 使用指南

[返回项目首页](../README.md) · [文档索引](README.md)

## 安装与启动

按照[首页快速开始](../README.md#快速开始)安装依赖并构建。程序由本机 Node 服务提供网页，浏览器访问服务地址即可使用。

建议首次使用显式指定独立目录：

```bash
WORKBENCH_DATA_DIR="$HOME/ScientificWorkbench-preview" pnpm start
```

默认地址为 http://127.0.0.1:4317/ 。重新启动时使用相同的目录，才能继续之前的记录。需要现成内容时，先看[演示指南](DEMO.md)。

## 记录一份实验

1. 在样品页创建样品，填写名称与实验正文。
2. 用父级条目记录操作，子级条目记录条件、结果或补充说明。
3. 输入 `[对象名]` 引用原料、设备或过程。找不到时选择已有对象或明确创建，程序不会自行猜测类别。
4. 使用 `[对象]｜属性：值` 记录条件。普通文字、无法结构化的说明也可以保留。
5. 关注保存和提取状态。正文保存与属性提取是不同步骤；保存失败或冲突时，先处理提示再继续切换或导出。

程序保存的是实验记录，不会判断数值、单位或实验结论是否正确。特别是外部 AI 生成的文字，应对照原始记录核查。

## 数据、分析和论点

| 概念 | 用途 |
| --- | --- |
| Sample | 某个样品的操作记录与属性 |
| Data | 一份独立数据，可包含原始文件、图像、派生结果和说明 |
| Analysis | 将样品、数据与其他资料组织在一起，保存分析布局并导出上下文 |
| Claim | 从 Data 或 Analysis 建立的正式论点，附创建时的固定证据 |

同一 Data 可以被多个 Sample 引用。删除正文中的引用不等于删除独立数据或原始附件。不同入口同时修改 Data 时，需要处理版本冲突。

Sample 正文里的 `[论点]` 只是文本。需要固定证据的正式论点，应从 Data 或 Analysis 页面创建。证据固定后不会随来源后续修改而自动更新，也不意味着论点已经得到证明。

## 数据放在哪里

启动目录的选择顺序：

1. 显式 `WORKBENCH_DATA_DIR`。
2. 已保存的工作区启动选择。
3. 默认 `~/ScientificWorkbench`。

macOS 默认启动选择文件位于 `~/Library/Application Support/ScientificWorkbench/runtime.json`。可以通过 `WORKBENCH_RUNTIME_CONFIG` 指定其他选择文件。

工作区中保存样品、Data、分析、论点、字典、附件及证据等文件。格式见[文件格式](FILE_FORMAT.md)。不要将“只备份 SQLite”当作完整备份，也不要在服务运行时直接修改内部清单来修复问题。

## 备份与恢复

在设置中使用备份功能。备份包含业务文件与所需附件；凭据、缓存及索引不作为业务备份内容。使用远端附件时，备份需要能够读取并验证相关字节。

恢复会验证归档并创建新工作区，不覆盖原目录。普通启动可在下次重启时采用恢复后的目录；若设置了 `WORKBENCH_DATA_DIR`，该变量优先，需要自行改成恢复后的路径。恢复后需要重新配置被排除的凭据。

旧格式不能直接当作新版工作区打开，操作前阅读[迁移指南](MIGRATION.md)。

## 外部 AI

通过 [MCP](API_MCP.md) 可以让外部客户端访问授权范围内的数据；[OpenCode](OPENCODE_INTEGRATION.md) 是可选连接。不开启这些连接也能使用常规记录功能。

目前没有已开放的“上传实验记录图片并自动创建样品”入口。Vision 测试脚本是开发验证工具，不是用户导入命令。

## 常见问题

- **端口被占用**：设置 `WORKBENCH_PORT`，并在浏览器使用相同端口；不要直接终止不认识的服务。
- **页面没有更新**：构建启动需要先运行 `pnpm build`；开发模式访问 5173。
- **数据看起来消失了**：先核对本次 `WORKBENCH_DATA_DIR` 是否与上次相同。
- **保存冲突**：保留当前草稿，按界面提示比较或加载新版本；不要用删除索引来解决并发冲突。
- **服务报告 recovery required**：当前事务需要恢复，保留工作区与日志，按错误提示处理；不要绕过保护继续写入。
- **需要反馈**：记录复现步骤、提交号和错误信息，移除凭据、真实实验内容及敏感路径后提交 [Issue](https://github.com/ZanderKong/scientific-workbench/issues)。
