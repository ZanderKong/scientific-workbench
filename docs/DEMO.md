# 演示与人工检查

[返回项目首页](../README.md) · [使用指南](GETTING_STARTED.md)

样例用于检查软件流程。CSV、PNG、说明文件及全部数值都是模拟内容，不是实测数据或论文证据。

## 创建并打开样例

先在仓库根目录完成依赖安装与构建，然后执行：

```bash
pnpm demo
WORKBENCH_DATA_DIR="$PWD/demo/workspace" pnpm start
```

访问 http://127.0.0.1:4317/ 。生成器只接受不存在的目标目录；若 `demo/workspace` 已存在，直接启动即可，不必重新生成。

需要另一份独立样例时，使用全新目录，并让生成与启动使用相同路径：

```bash
WORKBENCH_DEMO_DIR="$PWD/data/demo-02" pnpm demo
WORKBENCH_DATA_DIR="$PWD/data/demo-02" WORKBENCH_PORT=14321 pnpm start
```

访问 http://127.0.0.1:14321/ 。不要将真实工作区作为 demo 目标；生成器不会删除或覆盖已存在目录。

## 样例内容

| 项目 | 检查重点 |
| --- | --- |
| PVA-01 | 一次独立冻结和解冻操作 |
| PVA-03 | 三次冻结、三次解冻，独立步骤和区块 |
| PVA-EG | 乙二醇配方与名称带空格的设备 |
| Draft-01 | 错配括号、无效属性、未绑定对象及普通论点文本 |
| Import-01 | 独立 Data、多个 About 样品、CSV 与说明组件 |
| Analysis-01 | 样品与共享 Data、模拟图像、上下文导出及正式 Claim |

`Import-01` 是生成器建立的确定性样例，不是图片识别的输出。模拟曲线附件用于附件流程检查，不代表科学绘图能力。

## 建议人工检查顺序

1. 打开样品列表与 PVA-03，核对多次操作能否正常阅读。
2. 修改普通正文，等待保存，刷新并重开核对内容。
3. 使用真实中文输入法输入、选字，检查候选菜单、光标和保存状态。
4. 检查对象引用和属性；普通文字与错误语法不应丢失。
5. 从样品和数据页分别打开关联 Data，检查附件、说明与版本冲突提示。
6. 打开 Analysis-01，检查条目顺序、上下文导出和正式论点的固定证据。
7. 在独立样例上检查备份恢复；恢复到另一个全新目录后再重开。

生成后的 `exports/` 包含 `context.md` 与 `manifest.json`。后续编辑不会自动重写已经导出的副本，需要重新导出。

反馈时记录页面、步骤、预期和实际结果。人工查看通过不代表真实 Vision 或 restricted profile 已通过；相关状态见 [STATUS.md](STATUS.md)。
