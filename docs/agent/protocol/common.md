# 协议：通用规则（protocol-common）

适用于所有科研读写任务。

## 1. 文件优先（file-first）

- 科研文件与 list 才是事实源，SQLite 索引只是可重建缓存。Agent 不能假设数据库里有额外事实。
- 只能通过 API/MCP 修改；禁止直接访问数据目录、附件字节或 SQLite。
- 读取“最新结构”前，相关文档必须已完成提取；返回旧索引冒充最新是错误。

## 2. 稳定身份

- 实体、区块、对象都用 UUID 身份；显示名、编号、行号都不是身份。
- 正文每个 bullet 前有 `<!-- swb:block id="..." -->` 标记；移动保留，复制生成新 ID。
- 引用绑定以稳定 `blockId` + 原文范围定位，不以行号定位。

## 3. 保存、提取与版本

- 保存正文（`document_save`）与完成提取（`document_finalize`）是两步：保存后仍是 `pending`，提取成功才是 `ready`。
- 修改一律携带 `expectedVersion`。收到 409 时保留你的草稿，重新读取当前版本，再决定如何协调；不要盲目重放。
- 保存失败不改变已落盘正文。不要用旧版本强行覆盖新内容。

## 4. 幂等与重试

- 创建类操作使用幂等键。相同键+相同载荷返回同一结果，不重复创建。
- 网络超时/响应丢失时，先读取确认是否已经成功，再决定重试；不要把“没收到响应”当成“没执行”。

## 5. 歧义不臆造

- 数量、归属、单位、对象身份/类别等关键歧义未澄清时，不要写入已确认结构值。
- 用 Question 澄清（若运行环境提供），或保留普通“待确认”文本；后者不能成为已确认属性或正式论点。
- 不要创建猜测类别的对象；只有明确复用或来源/用户澄清支持的明确新建才可创建。

## 6. 数据位置 provenance

- 精确的页/行/表格位置优先保存在来源 Data 的组件 provenance 中，而不是模板化追加到每个 Sample 正文。
- 只有当来源位置本身具有科研记录意义时，才在正文保留。
- Sample 与共享 Data 的正式绑定由 `[数据]` 区块承担，不要求逐条“来源第几页第几行”。

## 7. 权限失败

- 权限失败返回明确错误；不能换用别的工具/路径绕过。请求用户授权或缩小任务范围。
