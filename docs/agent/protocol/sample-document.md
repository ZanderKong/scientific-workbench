# 协议：样品与正文语法（protocol-sample-document）

依赖：`protocol-common`、`guide`。持久化字段见 `docs/DATA_PROTOCOL.md`，本文只讲语义与写法。

## 1. 文档模型

- 一个 Sample 对应一份 Document；正文是科研记录的事实源。
- 一级 bullet 是一次操作（RecordUnit），建议一次搅拌/加热/添加/测试一行。
- 二级 bullet 承载该操作中对象的属性，或一个 Data 行。
- 普通观察文本不加任何标记，原样保存。

## 2. 对象引用真实语法

对象统一写作 `[名称]`，也接受成对的 `【名称】`、`［名称］`。名称允许空格、数字、连字符、圆括号；不支持嵌套方括号，也不支持错配的 `[名称】`（保留为普通文字）。

```text
- 使用 [磁力搅拌器]，将 [水] 加入 [样品A]，进行 [搅拌]
  - [水]｜添加量：80 g
  - [磁力搅拌器]｜档位：2
  - [搅拌]｜转速：500 rpm｜时间：30 min
- 样品呈淡黄色，有少量气泡
```

上面第三行是普通观察文本：不会被提取为属性，也不会创建对象。

## 3. 属性的存储归属

- 属性行严格为：行首一个 `[对象]`，随后 `｜属性名：值`，可继续 `｜属性名：值`。竖线和冒号接受全/半角，可混用。
- 名称与值去首尾空白后都必须非空；值可含冒号，不可含竖线。
- 所有有效属性值记录在当前 Sample 上（对象 + 属性 + 文本值 + 来源区块）。不存在“对象全局属性”被就地改写；资源对象的推荐属性与推荐单位只是填写提示。
- 没有独立的 sample-level 行类型：描述样品整体性质的属性同样写在操作上下文中，只是它描述的是样品综合状态。不要发明“任意 root 文本即属性”。

```text
- 配制 [前驱体溶液]
  - [前驱体溶液]｜pH：4.2｜外观：澄清
  - [2POA]｜添加量：5 g
```

`2POA` 的角色必须先依据已有对象/别名或明确澄清确定；`5 g` 是操作内对象用量，不是自动升级为样品级数值。

## 4. 类型标记

- 行首 `[数据] 名称` 标记一个 Data 区块；其受限子级承载附件或普通文本。
- 行首 `[论点] 文本` 在 Sample 中只是普通文本，不会创建正式 Claim。
- 重复或错配的类型标记会被拒绝，不要指望后端猜你想要的类型。

## 5. 保存、版本与提取

- `document_save` 保存正文；保存后可携带 bindings 绑定已有对象，但不允许借 bindings 修改文件头、版本或 Data 镜像基线。
- 空 bindings 数组会清空 references；省略 bindings 保留原 references。
- 保存后调用 `document_finalize` 完成整篇提取。返回 `stale` 时必须先重新读取，不能把旧结构当最新。
- 编号缺省由服务器生成；显式 code 冲突必须处理，不要静默改名丢失记录关联。

## 6. 数据区块与共享 Data

- `[数据]` 区块必须显式绑定到某个现有 Data。未绑定的数据区块在首次提取时会被视为新建，可能产生重复 Data。
- 同一份来源数据（例如一组实验记录图片）只创建一个 shared Data，供多个 Sample 通过各自的 `[数据]` 区块正式引用；不要按 Sample 复制图片或 Data。
- 页/行/表格位置存放在来源 Data 组件的 provenance；只有当该位置本身是科研事实时才写入 Sample 正文。

## 7. 引用创建意图

- 没有合适对象时，编辑器写入明确 create-intent：`status: create-intent`、UUID `intentId`、角色限定原料/设备/过程。
- 完成提取时校验区块、范围与原文仍匹配，才在同一事务中创建对象；修改或删除文字即解除意图。
- Sample 自身由 `sample_create` 产生，不能通过引用意图创建。
